# 자리봄 (JariBom)

> **공모전 제출 정보**
> - 앱 이름: 자리봄 (JariBom)
> - 한 줄 소개: 운전석을 떠날 수 없는 운전자를 대신해, 내리는 동승자에게 한마디를 건네고 그가 떠난 빈 좌석(창문·열선·통풍·키즈락 잠금)을 정차 중 안전 조건 안에서 정리하는 Pleos 차량용 앱
> - 버전: 1.0.0 (versionCode 3)
> - APK: [`apk/자리봄팀_자리봄_release.apk`](apk/) (release 빌드)
> - 테스트 환경: Pleos Connect 에뮬레이터 v2.1.0 (Android 14, API 34) + Pleos Connect Virtual Console, Pleos SDK 2.3.2, minSdk 28
> - 화면 규격: (에뮬레이터 화면 해상도 기입 예정)
> - 실행 방법: 에뮬레이터를 켠 뒤 `adb install -r -t --user 10 apk/자리봄팀_자리봄_release.apk` → 앱 실행 → 속도 권한 허용 → 설정에서 키즈락 좌석·챙길 물건 지정 → Virtual Console로 신호 입력(아래 "에뮬레이터 시연" 참고)
> - 필요한 설정: 날씨 안내를 쓰려면 빌드 때 `local.properties`에 `KMA_SERVICE_KEY`(기상청 단기예보 API 키)를 넣습니다. 키가 없어도 다른 기능은 모두 동작합니다.

동승자가 내리면 그 좌석을 대신 정리하고, 두고 내린 물건을 놓치지 않게 알려 주는 차량용 앱입니다. 운전자는 화면을 보지 않고도 "누가 탔고, 무엇이 정리됐는지"를 말과 알림으로 받습니다.

## 하는 일

### 핵심 3묶음
1. **말하기**
   - 탑승이 확정되면 "{좌석}에 탑승을 확인했어요. 편하게 가세요."라고 인사합니다(설정 "탑승 멘트").
   - 동승자가 내리려고 문을 열면 챙길 물건과 날씨를 그 사람에게 안내합니다(설정 "하차 멘트"). 아이 좌석은 아이 말투로 말합니다.
   - 동승자 안내가 큐에서 밀려 재생 차례에 문이 닫힌 지 5초가 넘었거나 차가 달리고 있으면 말하지 않고 버립니다.
2. **정리**
   - 하차가 확정되면(착좌 해제 + 그 좌석 문 열림 → 닫힘) 그 좌석 창문 닫기, 열선·통풍 끄기, 아이 좌석 창문 잠금 되돌리기를 합니다.
   - 쓰기 직전에 안전 게이트를 다시 검사하고, 값이 목표에 닿았는지 읽어서 확인합니다.
3. **보고**
   - 실제로 한 일만 운전자에게 알림으로 보고합니다(기어 P이고 정차일 때는 음성도 함께). 실패하면 이유와 [다시 시도] 버튼을 줍니다.

### 보조
- **남은 물건 확인**: 같은 때 내린 다른 좌석 옆에서 문만 열렸다 닫히고 사람은 벨트를 푼 채 남은 좌석이 있으면 "무언가 남아 있는 것 같아요"라고 알립니다. 열선·통풍이 켜져 있으면 [끄기] 버튼을 붙입니다(자동으로 끄지 않습니다).
- **아이 좌석 모드**: 뒷좌석을 아이 좌석으로 지정하면 탑승 때 창문 잠금을 걸고, 하차 때 원래대로 돌립니다. 어른이 탔으면 알림의 [어른이 탔어요]로 이번 운행만 일반 안내로 바꿉니다.
- **택시 모드**(기본 꺼짐): 운전석을 뺀 모든 좌석에 아이 좌석 보조 판정(출발 때 확인 알림 1번)을 적용합니다.
- **익명 사용 통계**(기본 꺼짐): 옵트인. 20개 키(schemaVersion 2)의 월별 합계만 만들고, 지금은 로그로만 출력합니다(네트워크 코드 없음). 정리 성공률은 `restores / (restores + restoreFailures)`로 계산하고, `retained`는 "이번 달 4회 이상 사용(사용 강도)"이며 유지율(Retention)은 `installMonth`(설치한 달) 코호트로 따로 계산합니다.

## 안전 원칙
- **운전·도어 능력 없음**: 운전 기능과 문 열기·닫기·잠금(차일드락 포함) 명령이 앱에 없습니다. 테스트(`VehicleCapabilityTest`)가 허용된 명령 목록을 고정합니다.
- **쓰기 권한은 2개뿐**: 창문(`CONTROL_CAR_WINDOWS`), 시트 열선·통풍(`CONTROL_CAR_SEATS`). 공조 쓰기 권한은 없습니다.
- **운전석은 제어하지 않습니다.** 권한이 있어도 안전 게이트가 막습니다.
- **음성 규칙 2종**
  - 운전자 보고 음성: 기어 P이고 정차일 때만.
  - 동승자 하차 안내 음성: 문이 열릴 때 허용(문 열림을 정차 증거로 봄). 속도 값이 있고 |속도| > 0.5 m/s이면 하지 않습니다.
- **안전 게이트**: 매 쓰기 직전에 검사합니다. 사람이 앉아 있거나 문이 열려 있는 좌석의 창문 닫기와, 사람이 앉은 좌석의 창문 잠금 해제는 거부합니다.
- **창문 닫는 도중 정지**: 닫히는 동안(최대 16초) 그 좌석을 지켜보다가 문 열림·착좌·벨트 체결이 생기면 쓰기를 멈추고 자동으로 다시 닫지 않습니다. 차량 자체의 끼임 방지의 보조입니다.
- **좌석 신호 모드 3종**: FULL(착좌·벨트 모두), BELT_DOOR(착좌 센서가 없는 좌석: 벨트와 문으로 판단, 창문은 알림 [창문 닫기]를 눌러야 닫음), NONE(신호 없음: 관리하지 않음).
- **재연결**: 차량 서비스가 죽으면 쓰기를 막고 1·2·4·8·16·30초 간격으로 다시 붙습니다. 다시 붙은 뒤 결과를 못 받은 창문은 다시 읽어 확인합니다(새로 닫지 않음).

## 빌드와 테스트

플레이버가 둘입니다. `pleos`는 Pleos 차량·TTS SDK를 쓰고, `mock`은 SDK 없이 일반 Android에서 디버그 패널로 차량 신호를 흉내 냅니다.

```
./gradlew :app:testMockDebugUnitTest :app:testPleosDebugUnitTest   # 단위 테스트 (플레이버마다 233개)
./gradlew :app:assemblePleosDebug                                   # 디버그 APK
./gradlew :app:assemblePleosRelease                                 # 릴리스 APK
```

- `testDebugUnitTest`는 플레이버가 모호해서 쓰지 않습니다.
- 날씨 API 키는 `local.properties`의 `KMA_SERVICE_KEY`에서 읽고, 릴리스 서명 키는 `RELEASE_STORE_FILE` 등으로 읽습니다. 둘 다 저장소에 없습니다. 서명 값이 없으면 릴리스 APK는 서명 없이 만들어집니다.
- 디버그 전용 기능(디버그 패널, 기록 초기화, 수동 신호 지정, 좌석 신호 강제)은 릴리스에서 보이지 않습니다.

## 에뮬레이터 시연

Pleos Connect 에뮬레이터의 Virtual Console(HTTP API)로 차량 신호를 넣습니다. 포트 포워딩(`adb forward tcp:8088 tcp:8088`) 후 작업하는 동안 `POST /browser/session?client=<id>`를 1초마다 보내고, 읽기는 `GET /vehicle/state`, 쓰기는 `PUT /vehicle/{gear|seat|body|hvac}`를 씁니다. 콘솔의 Window Lock 표시는 쓰지 않습니다(앱이 읽는 값과 이어져 있지 않습니다).

하차 시연 순서는 실제 하차와 같게 **문 열기 → 1~2초 → 착좌 해제 → 문 닫기**입니다. 시나리오가 끝나면 기준 상태(기어 P, 문 닫힘, 착좌 없음, 창문 0, 열선·통풍 0)로 되돌립니다.

## 알려진 한계
- 하차 정리는 착좌 신호가 있어야 정확합니다. 착좌 센서가 없는 좌석(BELT_DOOR)은 벨트를 안 맨 승객을 탑승으로 인식하지 못하고, 앉은 채 벨트를 푼 상태에서 문이 한 번 열렸다 닫히면 가짜 하차가 확정될 수 있습니다(창문은 자동으로 닫지 않아 안전).
- 차량 서비스가 끊긴 동안 일어난 문 열림·착좌·하차는 놓칩니다. 끊기기 전에 SDK로 넘어간 쓰기는 다시 붙을 때 뒤늦게 실행될 수 있습니다.
- 창문 닫는 도중 정지는 SDK에 창문 정지 API가 없어 현재 위치를 다시 쓰는 방식입니다. 차량이 실제 위치가 아니라 마지막 목표값만 돌려주면 정지가 듣지 않을 수 있습니다.
- 음성 타임아웃은 끝 신호가 없는 경우라 실제로는 재생됐어도 실패로 셀 수 있습니다.
- 에뮬레이터는 차속 권한이 없어 정차·주행을 기어로 판정합니다.
- 쓰기 마지막에 읽는 값이 늦게 반영되는 차에서는 재연결 뒤 창문 확인이 "위치 그대로"로 보일 수 있습니다.
